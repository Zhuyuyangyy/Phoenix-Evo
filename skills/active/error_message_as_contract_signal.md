## When to Use
当任务遇到 Python 报错信息（Traceback）时，把错误类型当作接口契约的违反信号：
- TypeError → 签名/参数契约违反
- SyntaxError → 文件内容损坏或格式错误
- ImportError → 模块路径/版本/名称契约违反
- AttributeError → 对象结构契约违反
通过错误类型推断错误根源，比猜原因快 5-10 倍。

## Procedure
1. **提取错误类型作为第一信号**：TypeError → 查签名；SyntaxError → 验证文件完整性；ImportError → 查路径
2. **按错误类型走对应路径**：
   - TypeError: inspect.signature() → 确认参数名和数量 → 修正调用
   - SyntaxError: 读文件前 10 行 → 检查缩进/括号/字符串配对 → 定位损坏位置
   - ImportError: help(module) / __all__ 查可用名称 → 确认版本和导入路径
   - AttributeError: hasattr() 检查属性 → 读源码确认属性名或使用 getattr(obj, name, default)
3. **记录错误类型作为技能挖掘素材**：把「错误类型 → 根因 → 修复路径」存入 Phoenix trajectory
4. **高频 ImportError 处理**：优先用 try/import 捕获，确认是路径问题还是名称问题再决定是修代码还是装包
5. **AttributeError 特殊处理**：检查属性是否存在 hasattr()，如果存在但仍报错，可能是继承层次或 mixin 问题

## Failure Cases
| 错误阶段 | 错误信息 | 修复策略 |
| -------- | -------- | -------- |
| TypeError 反复出现 | 每次调用都报不同参数错误 | 用 signature() 完整读取函数签名，用 kwargs 传参避免位置错误 |
| SyntaxError 静默产生 | 写入后发现文件内容有空字节 | 用二进制读入检查 b'\x00' 出现位置，确认后从备份恢复 |
| ImportError 偶发 | 某些机器上 ImportError 某些不报错 | 统一使用绝对导入 from package import name 而非相对导入 |
| AttributeError 在 hasattr 为 True 时仍报错 | 属性存在但访问时报 Error | 检查描述符协议（property/descriptor），用 getattr 而非直接访问 |
