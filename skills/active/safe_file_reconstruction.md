## When to Use
当任务涉及覆写或修复可能损坏的源文件时（尤其是 .py .vue .html 等文本文件），先写 /tmp/ 临时文件验证合法性，再迁移到目标路径。
典型场景：patch 工具在 WSL 中文路径下写入 null 字节导致文件损坏；覆盖配置文件前没有备份；写入大文件时进程中断产生截断。

## Procedure
1. **读源文件前先备份**：cp original.py /tmp/original_backup.py
2. **写入前先写临时文件**：写到 /tmp/verified.py，用 ast.parse() 或 py_compile 验证语法
3. **验证后再迁移**：diff /tmp/verified.py 原始内容，确认无误后 mv /tmp/verified.py 目标路径
4. **如果文件不存在**：先 touch /tmp/empty_placeholder.py 再逐步写入关键内容
5. **ChromdDB/向量库文件**尤其注意：不要直接覆写 .sqlite .sqlite-journal 等数据库文件，先验证

## Failure Cases
| 错误阶段 | 错误信息 | 修复策略 |
| -------- | -------- | -------- |
| 写入损坏 | patch 写入 null 字节 | 立即用 /tmp 备份恢复：cp /tmp/original_backup.py 目标路径 |
| 语法未验证 | SyntaxError: unexpected EOF | py_compile 验证通过后再迁移 |
| 进程中断 | FileNotFoundError | 先检查文件是否存在，再决定是恢复还是重建 |
| 中文路径写入失败 | UnicodeEncodeError | 改用 /tmp 中转，写入前 os.fspath() 确保路径编码正确 |
